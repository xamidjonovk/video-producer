# Higgsfield production and credits

1. Build a rough cut and reusable character, set, prop and lighting references first. Use the user's real footage, licensed B-roll, stills suitable for compositing, motion graphics and existing approved assets before deciding what must be generated. Still frames make effective storyboard plates. Final scenes that need visible action require motion footage.
2. Decide the target aspect ratio, output size and the shortest usable shot. Look up the current model and accepted input roles. Choose a model for each shot's needs such as reference continuity, native sound, audio-driven speaking, or movement. For expensive dialogue or movement, test one representative shot before the full batch.
3. Prefer a model's real draft-to-final flow for shots likely to need iteration. Higgsfield documents Seedance 2.5 Draft Mode as a lower-resolution moving preview with a separately charged final step. On the connector, check the active model schema for `draft` and `draft_job_id`. Price-check both steps and compare the total with a direct final. For other lower-resolution renders, treat the clip as a movement test. Raising resolution by regenerating can change the performance. Watch the final export with audio and inspect it at the intended resolution.
4. Use the connector's estimate with the exact resolution, duration, inputs and number of variants. Record current quotes and existing job IDs. For a specific quoted request use its supported quote reference. Keep reattempts small: change one key prompt, reference or shot direction, then retest. If the movement and face work, consider fixing only color, subtitles, background edge or audio in Resolve. Verify output and final continuity before continuing.
5. Separate web entitlements, paid connector usage and model-specific user quotas. Verify live access and effective cost on the chosen surface. Never budget web unlimited for a connector call unless the current tool confirms it for that exact job. Avoid buying extra credits or using premium spending without the necessary authorization.
6. Use `credit_plan.py` for a concrete ceiling. `spent` covers prior jobs, `reserve` is optional, and `shots` lists pending uniquely identified line items as `{ "id": "s01-draft", "quoted_credits": 30, "count": 1 }`. Pending final renders and retry variants need separate entries. Always match the real job against the reviewed quote and update the ledger before the next submission. A failed charge stays spent until the provider confirms a refund.
